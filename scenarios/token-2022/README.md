# Token-2022 scenarios

One scenario per mint extension, generated by `generate.py` from `token-universe/universe.csv` (2026-10-07). A token is relevant with at least $1.0M of 90-day DEX volume, of which at least 5% in the last 30 days (so launches that have since died drop out), and $50k of liquidity (166 Token-2022 tokens). Positive scenarios also need a CoinGecko listing and a Jupiter price above zero.

Tokens carry extensions as bundles, so one token can show up in several files: xStocks carry pausable, scaled UI amount, default account state, permanent delegate, confidential transfers and an empty transfer hook; the stablecoins (USDG, PYUSD, CASH) add mint close authority and a 0-bps transfer fee.

| [Metadata only (metadata pointer + token metadata)](https://solana.com/docs/tokens/extensions/metadata) | Name, symbol and URI live on the mint itself instead of a separate Metaplex account. It doesn't touch transfers. The most common Token-2022 shape: pump.fun and most new launches. | Tradable. | 76 | 20 | [metadata-only.csv](metadata-only.csv) |
| [Transfer hook, no hook program set](https://solana.com/docs/tokens/extensions/transfer-hook) | Every transfer calls a program the issuer chooses (allowlists, royalties, compliance). These mints carry the extension with no program set, so transfers behave normally, but the issuer can set one later. | Tradable while unset. | [Permanent delegate](https://solana.com/docs/tokens/extensions/permanent-delegate) | An authority that can transfer or burn tokens from any account of this mint, forever: issuer clawback for regulated stablecoins and tokenized stocks. | Tradable. | [Confidential transfers](https://solana.com/docs/tokens/extensions/confidential-transfer) | Accounts can opt in to encrypted balances and amounts, proved with zero-knowledge proofs. | [Mint close authority](https://solana.com/docs/tokens/extensions/close-mint) | An authority can close the mint account once supply is zero, to reclaim its rent. No effect on transfers. | Tradable. | 5 | 4 | [mint-close-authority.csv](mint-close-authority.csv) |
| [Default account state](https://solana.com/docs/tokens/extensions/default-state) | Sets the state new token accounts start in. `frozen` means the issuer must thaw each account before it can hold tokens (KYC gating). Every relevant mint uses `initialized`, so accounts work immediately. | Tradable when `initialized`. The backend's mint rules reject `frozen`: the settlement couldn't pay into a new account. | 65 | 20 | [default-account-state.csv](default-account-state.csv) |
| [Pausable](https://solana.com/docs/tokens/extensions/pausable) | An authority can pause every transfer, mint and burn of the token at once (an emergency stop, used by xStocks). All relevant mints are running. | Tradable while running. While paused, transfers fail, so orders can't settle until it resumes (untested: no relevant mint is paused). | 65 | 20 | [pausable.csv](pausable.csv) |
| [Scaled UI amount](https://solana.com/docs/tokens/extensions/scaled-ui-amount) | Displayed balances are the raw amount times a multiplier the issuer can change, to reflect stock splits and dividends (xStocks). Raw amounts on chain don't change. Watch the amounts: sim sizes rows in UI units from prices, so a multiplier far from 1 skews them (the 60% sell-back leaves room). | Tradable. | 63 | 20 | [scaled-ui-amount.csv](scaled-ui-amount.csv) |
| [Transfer fee config at 0 bps](https://solana.com/docs/tokens/extensions/transfer-fees) | A transfer fee is configured but set to 0 bps, so recipients get the full amount. The fee authority can raise it; a new fee takes effect two epochs after it's set. | Tradable since early Oct 2026 (rejected before). A fee raised later would make the token unsupported. | 4 | 2 | [transfer-fee-zero.csv](transfer-fee-zero.csv) |
| [Transfer fee above 0 bps (expected rejections)](https://solana.com/docs/tokens/extensions/transfer-fees) | Each transfer withholds a fee (in bps, up to a cap) in the recipient's account for the issuer to harvest. Every row is expected to fail, so nothing is spent. | 25 | 25 | [transfer-fee-rejected.csv](transfer-fee-rejected.csv) |

## Extensions no relevant token uses

Documented so they aren't missed; there's nothing liquid to test them with.

- [Interest-bearing](https://solana.com/docs/tokens/extensions/interest-bearing-tokens): Displayed balance accrues interest at a rate the issuer sets; raw amounts don't change.
- [Non-transferable](https://www.solana-program.com/docs/token-2022/extensions#non-transferable-tokens): Soulbound: tokens can't move after minting, so they can't be traded at all.
- [Transfer hook with a program set](https://solana.com/docs/tokens/extensions/transfer-hook): Every transfer runs the issuer's program. Barn's handling is untested: no relevant token has one.
- [Group and member pointers](https://solana.com/docs/tokens/extensions/group-member): Link a mint to a collection (like NFT collections). No effect on transfers. The universe hides them like metadata.

## Account extensions

These live on a holder's token account, not on the mint, so the token picks don't cover them.

- [Immutable owner](https://solana.com/docs/tokens/extensions/immutable-owner): Default on associated token accounts; nothing to test.
- [Required memo on transfer](https://solana.com/docs/tokens/extensions/memo-transfer): Incoming transfers need a memo instruction first.
- [CPI guard](https://solana.com/docs/tokens/extensions/cpi-guard): Limits what programs can do with the account through cross-program invocations.

## Regenerate

```
cd sim && pnpm sim build-token-universe   # refresh token-universe/ (barn quotes, extensions, volume)
cd .. && python3 scenarios/token-2022/generate.py [--min-volume 1e6] [--per-file 20]
```
